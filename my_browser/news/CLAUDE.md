# CLAUDE.md: news (the radar)

This part is OnePath's radar of opportunities: hackathons, competitions, schools, internships, research programs, grants, conferences, each with its deadline. It reads them from many sources, merges the posts about one opportunity into a story, has the LLM read each story and gives the app its list. The package keeps DEEper's name (`my_browser/news`), where it read AI news in a second lane; the same paths keep fixes portable between the repositories. This file covers what it does, how to run and check it alone, what core expects from it and what it expects from the rest. The repository's rules are in the root CLAUDE.md; open work is in the root `plan.md`, and the sources checked and refused are listed at the end of this file. Paths below are relative to `my_browser/` unless they are repo-root files.

## What the radar does

In short: collection from public Telegram channels, feeds, programs' pages, Devpost and awesome-mlss, and once a week from the web; merging posts into stories; cutting roundups into single announcements and reading each story with the LLM against the user's profile; the app's list updated once a morning within a window of three months (six for an especially big one), the tracked deadlines of the next two weeks on top («Скоро дедлайн», where DEEper's bot sent reminders); a calendar of big annual events awaited; settings and sources from the app's «Настройки»; a daily copy of the database.
- `news/db.py`: everything the radar keeps, in `REPORTS_DIR/news.sqlite` (WAL): `sources`, `items`, `stories`, `opportunities` (one row per story: type, deadline, conditions, fit, the user's status), `settings`, `state`, `opps_spend`. Columns newer than a table go into `ADDED_COLUMNS`, so an older file on the volume gets them.
- **The database came from DEEper.** On 27.10.2026 DEEper's `news.sqlite` was copied to OnePath's volume with its news lane cut out (HANDOFF.md): its sources, posts, stories and opportunities kept their ids, the user's statuses and what the morning updates had shown. Every row OnePath writes has `lane = 'opps'`, and every query on `sources`, `items` or `stories` says so: eight of DEEper's news sources stay in the table switched off (lane `news`), because eight posts of the lane are copies of their AI news (DEEper's scoring copied a news story that announced an opportunity, among them AI Journey 2026, which the user registered for). `sources.listing()`, `enabled()`, `due()` and `manage.find()` leave them out; one switched back on joins the lane `opps`.
- `news/sources.py`: the sources table and the starting list (`DEFAULTS`): 64 sources of 52 owners, checked in DEEper on 25.10.2026 (about 230 candidates; the ones refused are listed at the end of this file), six channels added on 26.10.2026 when the VI Congress of Young Scientists was found missing (Наука.рф `npnauka`, «Научные конференции» `confsci`, Росмолодёжь.Гранты, ICPC News, ITMO's career centre, «Сияние ИТМО»). Aggregators of hackathons and competitions, Devpost's online hackathons, awesome-mlss's schools, AI safety programs, companies' and ITMO's channels, conferences and grants.
  - Categories `aggregator`, `company`, `university`, `program`, `conference`, `community`, polled by `OPPS_INTERVALS`; a page once a day (`PAGE_INTERVAL`). Several channels of one company share its owner (`yandex`, `sber`, `itmo`), so a story counts independent owners, not channels. The faculty's and the lab's channels are deliberately not here: the user adds them in «Настройки» → «Источники».
  - Defaults are offered once (`state.offered_defaults`): a source the user removes does not come back, and one added to `DEFAULTS` later reaches existing databases at the next start.
  - `listing()` (`GET /sources`) gives each source its health and `week` (fresh posts of the last week), and an enabled one `silent_days` when no new post has been seen for longer than its kind usually stays quiet (`SILENT_DAYS`: an aggregator 14 days, a page 90, any other category `SILENT_DAYS_OTHER` 45); else `silent_days` is null. Silence counts from the newest post's `seen` (backfill included), so a new source's count starts at its first poll.
- `news/config.py`: the user's settings, defaults in `Settings`, changes in the `settings` table. Every value is checked; a refused change raises `SettingsError` with a message for the user in Russian (`explain()`), and a stored value that no longer passes is deleted at load (DEEper's news settings too, if one ever comes back), so its default applies.
  - `timezone`; `opps_enabled`; the morning update (`opps_digest_day`: `daily` by default, or a weekday for a weekly one; `opps_digest_time`, 08:00: the names are those of the Telegram digest it replaced in DEEper on 26.10.2026); the window (`opps_window_days` 92, `opps_major_window_days` 183 for an especially big one); `opps_types` (`OPP_TYPES`: the types the app shows; every type is read); `opps_search` (the weekly web search); `opps_budget_month_rub` (30 ₽, a tenth of it a day); `opps_profile`. The `opps_` names are DEEper's, kept so that the database brought over kept its values.
  - `opps_profile` is the text each opportunity's fit is scored against. The default is deliberately neutral: the repository is public, and the user's own profile is written in «Настройки» → «Профиль» (it was never set in DEEper, whose `/profile` the user had not used; on 27.10.2026 the profile of the user's plan of 25.10.2026 was put in at the move, `HANDOFF.md`). `clean_profile()` drops emails, links, handles and phone numbers before it reaches a prompt. `update()` notes a new profile in `state.opps_profile_at`: every opportunity still ahead is read again against it, once (`opps._waiting()`).
- `news/collectors/`: one module per kind of source, `async fetch(source, client) -> Fetched`; the same code as DEEper's.
  - `rss.py`: RSS and Atom (feedparser, parsed in a thread), with conditional GET (`etag`, `modified`): an unchanged feed answers 304.
  - `page.py`: a page without a feed (a program, a company's internships, an aggregator's list), once a day. Its main text (no menus, headers, footers, forms) is fingerprinted into `sources.page_hash`, the text kept in `page_text`. The first poll stores the page as a post; a program's page that changed gives its whole new text with «Изменилось на странице: …» at the end (the embedding reads the unchanged start, so the post joins its story), an aggregator's list (category `aggregator`) only its new lines, as a roundup. A change only in numbers, in lines that say nothing of deadlines or applications (`DEADLINE_WORDS`), is remembered without a post. Less than `MIN_TEXT` (200 characters) of text: a JavaScript site, refused.
  - `devpost.py`: Devpost's online hackathons through the JSON its pages read (`/api/hackathons`, nine a page, `MAX_PAGES`); a post per hackathon with its organizer, submission period, prizes and themes, dated when first seen.
  - `mlss.py`: the data file of awesome-mlss (machine learning summer schools): a post per school whose deadline has not passed, its id carrying the deadline, so a moved deadline is a new post. PyYAML comes with gpt-researcher.
  - `telegram.py`: public channels through the web preview `t.me/s/<channel>` (the last ~20 posts, no account). The first line stands in for a title; links come from the text, the link preview and a forward's original, and each link's address stays in the text («Регистрация (https://…)»), so the model can tell where to apply. The selectors are the page's HTML of 24.10.2026: if Telegram changes it, every channel fails at once with «no public preview» or yields no posts.
  - `__init__.py`: `Post`, `text_and_links()`, `link_key()`, `usable_key()`, `footer_key()`, `clean_url()`. A post keeps the keys of the pages it links to, without the scheme, `www.`, tracking and referral parameters, share buttons and its own site's pages. `usable_key()` says which keys may merge posts: a specific page, not a front page, a section like `/news`, a profile, a repository's owner or a newsletter's footer (`NEWSLETTER`). `clean_url()` follows VK's redirect (`vk.com/away.php?to=…`) to the address it leads to and decodes a host written in percent escapes («конгресс.наука.рф»).
  - A Telegram post with 4 or more links is a roundup (`Post.digest`, `telegram.is_digest()`): several announcements in one post, cut into parts by the model before merging. The channel's own footer does not count (`footer_key()`: a site's front page, a profile on a social network, `SOCIAL`): on 26.10.2026 «ВК | MAX | Сайт» under every post of ITMO STUDENTS made 18 of 55 announcements «roundups» in DEEper, among them the VI Congress of Young Scientists. `items.refresh_digests()` judges the stored ones again once after the rule changes (`state.digest_rule`, `DIGEST_RULE`).
- `news/items.py`: storing posts. `(source_id, external_id)` is unique, so a poll never stores a post twice.
  - A post stays fresh for `OPPS_FRESH_DAYS` (90; 30 until 26.10.2026, when the app's window became three months), on a source's first poll too: an announcement of two months ago may still be open. Older posts, and undated posts of the first poll, are stored as `backfill`: known, so they never come back as new, and never read. A backfill post a wider window makes fresh comes back whole the next time its source lists it (`REVIVE`: the text was cut to 300 characters); `widen_opps_window()`, at the loop's start, polls the sources again in full once after the window grew (their etags dropped, so a feed does not answer 304).
  - `slim()`, daily: posts older than `KEEP_TEXT_DAYS` (180) lose their text and embedding but keep their rows, so a feed that still lists them does not bring them back.
- `news/embed.py`: sentence embeddings (fastembed, `MODEL` = paraphrase-multilingual-MiniLM-L12-v2, 384 dimensions, chosen by DEEper's `eval/news`) in a child process (`python -m my_browser.news.embed`), so the model's few hundred megabytes go back after each batch. It is downloaded once (220 MB) into `REPORTS_DIR/.models`, or `NEWS_MODELS_DIR`. About 8 s for 300 posts on the Mac once downloaded.
- `news/dedup.py`: merging posts into stories, every 5 minutes (`loop.DEDUP_EVERY_SEC`), oldest post first.
  - A usable link shared with a post of an open story merges, if the two are not unrelated (`LINK_FLOOR` 0.35). A post that shares links with several stories joins the one with the most shared links, then the closest (`_nearest()`).
  - By meaning only posts of different owners, from `OPPS_THRESHOLD` (0.85) to both the story's first and closest post: announcements follow templates (aggregators' reposts of one announcement were 0.86–1.00 apart on 25.10.2026, unrelated posts up to 0.79, and under DEEper's looser news rules 69 Devpost hackathons became one story). Posts of one owner merge only by a shared link. A retelling in other words is the model's to merge (`same_as` in `opps.py`).
  - A watched page's new version joins its previous story; a link in `BOILERPLATE_POSTS` (4) or more posts of one source and nobody else's is its footer and merges nothing (`_boilerplate()`). A page the web search found (`discover.py`, kind `search`) is its site's for these rules (`_owner()`), not the search's: pages of one opportunity on different sites merge by meaning.
  - Posts wait to be merged for `items.OPPS_FRESH_DAYS`; a story stays open `OPPS_OPEN_DAYS` (60) after its last post or while its opportunity is open (`open`, `tracked`, `applied`), never once it `expired`.
  - `source_count` counts distinct owners; `title` is the earliest post's, until the model writes the opportunity's `title_ru`.
  - When the model cannot run (not downloaded, out of memory), posts are merged by shared links only and stored without an embedding: the reading goes on.
- `news/llm.py`: the LLM calls (Flash, through gpt-researcher's `create_chat_completion`) and their budget. Every call is metered (`common/costs.py`) into `opps_spend` by day in the settings' time zone; `within_budget()` stops the calls at the day's limit (`opps_daily_budget_rub`, a tenth of the month's 30 ₽) or the month's. Every call waits at most `ASK_TIMEOUT_SEC` (300 s), then is asked once more: on 25.10.2026 a call through the Mac's VPN hung for 20 minutes. `centroids()`, `same_as()` and `merge_into()` serve the reading's `same_as`. In DEEper these were the news scoring's (`news/scoring.py`).
- `news/opps.py`: the reading, after each merging run, within the budget; `opps_enabled` off stops it.
  - `split()`: a roundup (a channel's «5 хакатонов недели», an aggregator page's list, AISafety.com's weekly digest) is cut into one post per opportunity, each with its own address where the roundup gives one (`items.copied_from` points to the roundup, `split_at` marks it done); the next merging run places the parts like any post. A part without an address of its own keeps the roundup's, which merges nothing (`dedup.OWN_URL`).
  - What counts as an opportunity: something to apply or register for with a selection, a contest or submissions; since 26.10.2026 also a forum or congress for students and young scientists whose applications are reviewed (the Congress of Young Scientists, a case of `eval/opps`), but not a lecture, meetup or show one only attends. Both prompts say so.
  - `extract()`: each waiting story (`_waiting()`: never read; grown since, as a new post may carry a moved deadline; or still ahead and read before `major` existed or before the profile changed, `state.opps_profile_at`), `EXTRACT_BATCH` (6) a call, `MAX_PER_RUN` (60) a run, the newest stories first, up to `POSTS_PER_STORY` (3) posts each, the newest first: is it an opportunity, its type (`config.OPP_TYPES`), Russian title, organizer, summary, the deadline as written and as ISO with its time zone, `deadline_kind`, `closed`, the event's dates, format, place, eligibility, `ru_access`, cost, reward, where to apply, `fit` 0–10 against the profile (`config.clean_profile()`) with a reason, `major` (especially big, prepared for months ahead: international or national, a known organizer, a big prize or stipend, a selection in several stages; the app shows it within the longer window), and `same_as` among up to `SIMILAR_REFS` read opportunities closest by embeddings (the story is merged into it, `llm.merge_into()`). A story read again only for `major` or the profile (its posts unchanged, `grown` false) moves no deadline.
  - A story with no sign of an announcement in its posts (`SIGNAL`) is dropped without a call: a quarter of the collection of 25.10.2026, none of eval's opportunities. Pages, Devpost and awesome-mlss always go to the model (`ALWAYS_READ`).
  - `deadline()` checks dates, never trusts them: ISO only; the zone named in the text (AoE, UTC±N, PT, MSK, an IANA name), else Moscow's for a Russian source and UTC for an international one (`tz_assumed`); a date alone is the end of that day; a year off by more than a few is dropped. `apply()` stores the row: `dropped` (not an opportunity, with the reason), `expired` (deadline past, or `closed`), else `open`; `tracked`, `hidden` and `applied`, the user's, are kept. A tracked opportunity whose deadline a new post moved by more than a day keeps the old one in `deadline_moved_from` (with `deadline_moved_at`), which the app says («Дедлайн перенесён: 15 ноя → 29 ноя»; DEEper's bot sent a message). `expire()` runs every time: passed deadlines become `expired`, and an opportunity without a deadline whose event has begun too.
  - `read()` is the one extraction call, which `eval/opps/run_extract.py` measures with the same prompt and parsing; `listing()` serves `GET /opps`.
- `news/opps_delivery.py`: what the app shows. `run()` every tick:
  - The morning update (`release()`): every day at `opps_digest_time` (08:00), or once a week when `opps_digest_day` names a day, within `UPDATE_LATE_HOURS` (done dates in `state.opps_updates_done`), every open opportunity not shown yet (`sent_at` NULL), of the types on, within the window, goes into the list (`sent_at`); `state.opps_update` keeps when (`at`) and how many. One found during the day waits for the next morning. While nothing has ever been shown (a new database), every run releases, so a fresh list fills as soon as the first opportunities are read; then the mornings take over.
  - The window (`in_window()`): `effective()` — the deadline, else the event's start, since hackathons often give only their dates — at most `opps_window_days` ahead, `opps_major_window_days` for `major`; undated and all-year ones are always in it. A further one waits and comes in as new on the morning it enters the window.
  - `board()` (`GET /opps/board`, «Возможности»): `soon` (`soon()`: tracked opportunities whose exact or approximate deadline is at most `SOON_DAYS`, 14, ahead, the nearest first: in place of DEEper's reminders in Telegram 14, 3 and 1 days before; the user chose the app only on 27.10.2026), then the released ones within the window, each with `new` (released by the latest update), the new first by `order()` (how soon: two weeks, a month, later, unknown; then fit; low fit and no access from Russia last), then the rest by `by_date()`; `new`, `later` (open ones of the types on beyond the window), `updated` and `next` («сегодня в 08:00», with a no-break space), `window_days`, `major_window_days`, `expected` (`annual.expected()`).
  - `dressed()` adds what the app shows, so the screens format nothing themselves: `meta` (the caption, `meta()`: «Хакатон · дедлайн 12 ноя (через 18 дней) · онлайн · из РФ: да», words instead of colored marks, which the brandbook's palette lacks; once applied, the event's dates instead of the deadline, `event_when()`), `type_name`, `type_short` (`SHORT`, short enough for the app's filter on a phone), `apply` (where to apply, else the latest post's link), `details` (the sheet's `[label, text]` pairs of what is known — the deadline with its time and how soon, a moved deadline, as the announcement words it, the event's dates, format and place, who may apply, access from Russia, reward, cost, organizer, «Масштаб» for a big one), `major` (a bool), `over` (the event is behind: its last day, or its first without an end, before today; without dates, the deadline more than `OVER_DAYS` (30) ago) and `moved` (`moved()`: «Дедлайн перенесён: 15 ноя → 29 ноя» for `MOVED_DAYS`, 14, after the move). A deadline more than `MONTHS_FROM_DAYS` (60) days ahead reads in months («через 4 месяца»). `when()` is the «how soon» part, which `/status` also gives.
  - `set_status()` is the user's choice (`STATUSES`: `tracked`, `hidden`, `applied`, `open`); `by_date()` orders `/opps`.
- `news/annual.py`: big recurring opportunities (`EVENTS`: the Congress of Young Scientists, КМУ ИТМО, Yandex Cup, AIJ Contest, «Я — профессионал», ICPC, Потанин, Росмолодёжь.Гранты, ШАД, DLS, Yandex's and Kaspersky's internships, EEML, M2L, SMILES, AIRI's school, MATS, «Лидеры цифровой трансформации», «Диалог») with the month their registration usually opens, as their last editions had it (checked on 26.10.2026), the official page (checked to answer; «Лидеры» has none that answers from here) and a `pattern` that recognizes them. For `SEASON_MONTHS` (3) from that month, `expected()` lists an event of a type shown that no opportunity matches (read as one, first seen from `FOUND_MARGIN_DAYS` before the month): «Ждём» in the app, and a query of the weekly search. One the model dropped as «not an opportunity» is still awaited: that is a miss to see.
- `news/discover.py`: once a week (Monday 05:00, before the morning update; at once on a database that never searched, `state.opps_search_done` keeps the weeks done) the web is searched for what the sources missed. Flash writes `QUERIES` (12) queries from the profile without contacts, the types shown and the next six months (`QUERIES_PROMPT`), each awaited annual event adds one (`AWAITED_QUERIES`, 6 at most); they go to the web search (`common.settings.WEB_RETRIEVER`: Tavily on Railway, ≈ 75 of its 1 000 a month shared with DEEper's researches; the local SearXNG), `RESULTS_PER_QUERY` (5) each. A result the radar has not seen (its link_key among the posts and their links), one a site, not a social network, is fetched and read with `collectors.page.parse()` (the search's snippet for a page that shows nothing without JavaScript), at most `NEW_PAGES` (40), and stored as a post of the source «Поиск по вебу» (kind `search`, which `sources.due()` and `enabled()` leave out: the loop never polls it, «Настройки» → «Источники» switches it off like any source). Merging and reading then take the pages like any posts. On a real SearXNG run of 26.10.2026: 7 queries, 33 new pages in 64 s, among them the congress's registration, the Potanin scholarship, «Я — профессионал», the ICPC Moscow regional, Росмолодёжь.Гранты, MLSS 2027. The week counts as done whatever the engine answered, so an engine that is down costs one query-writing call a week. `opps_search` off stops it.
- `news/manage.py`: sources the user adds and removes in «Настройки» → «Источники»: a channel (matched case-insensitively), a feed (it must parse and have posts; its owner the feed's site) or, without a feed, a program's page with text without JavaScript (watched once a day, category `program`); added ones as `aggregator`. `add()` checks before it stores; an existing one is switched back on. `switch()` switches a source off (its posts stay in their stories; a starting source switched off is not offered again) or back on. Refusals raise `SourceError` with a message for the user.
- `db.backup()`, daily with `items.slim()`: a copy of `news.sqlite` in `REPORTS_DIR/backups`, the last 7 kept. Same volume: it guards against a broken file or a bad change, not against losing the volume.
- `news/loop.py`: the radar's loop, a plain thread that ticks every minute and marks each tick (`state.loop_tick`).
  - Each tick polls the due sources, at most `CONCURRENCY` (6) at once and one request per host at a time, `HOST_GAP_SEC` (2 s) apart (t.me serves a dozen of the channels).
  - A failing source waits twice its interval after one failure, four times after two, eight times after three or more (`sources.due()`).
  - `collect()` is shared with `POST /collect` and never runs twice at once (`_collecting`).
  - After a collection it calls `common.memory.trim()`, after the merging and reading run (every 5 minutes) `memory.release()`: the parsed feeds and pages would otherwise stay with glibc. Not `release()` every minute: its garbage collection holds the GIL, which pauses the web app.
- `news/api.py`: the FastAPI app behind the service token: `/status`, `/sources` (GET, POST), `/sources/find`, `/sources/{id}` (DELETE), `/sources/{id}/enable`, `/items`, `/stories`, `/opps` (`status`, `type`, `limit`), `/opps/board`, `/opps/run`, `/opps/update`, `/opps/{id}`, `/opps/{id}/status`, `/collect`, `/dedup`, `/settings` (GET, PUT), `/health`.

## Run and check it alone

```bash
uv run python -m my_browser.news      # API at 127.0.0.1:8504 (NEWS_PORT) + the loop
```

- With a throwaway `REPORTS_DIR` and your own `NEWS_PORT`, call it with the service token of that directory: `curl -s localhost:<port>/status -H "Authorization: Bearer $(cat <REPORTS_DIR>/.service_token)"`. In-process, without a server: `REPORTS_DIR=<dir> uv run python -c 'import asyncio; from my_browser.common.clients import call; print(asyncio.run(call("news", "GET", "/status")).json())'`.
- A wrong setting: `curl -X PUT .../settings -d '{"opps_window_days": 1}'` answers 422 with the message the app shows.
- **Collection.** The loop polls every source at its first tick (64 sources in about 100 s on 27.10.2026: 522 fresh posts of the last 90 days, 0 failed). `curl -X POST '.../collect?everything=true'` polls them all again: it should store only what is really new. `/items` lists the latest fresh posts, `/sources` each source's `last_error` and `fails`.
- **Reading.** `curl -X POST .../opps/run` cuts the waiting roundups and reads the waiting stories now (real Flash unless the mock's environment is set; the mock answers both prompts and the search queries), `/opps` lists what is open, `/opps/board` what the app shows, `/stories` the stories with their posts. `uv run eval/opps/run_extract.py` measures the reading on labeled real posts (about 1 ₽; see `eval/CLAUDE.md`). On a copy of a real `news.sqlite` two runs read about 120 stories for 2 ₽.
- **The morning update and the window** are checked with a simulated clock on a throwaway database: `opps_delivery.run(now=…, local=…)` and `board(now=…)`; `POST /opps/update` makes the update now, as the loop does when it is due.
- **Merging.** `curl -X POST .../dedup` merges the waiting posts now. DEEper's `eval/news/run_dedup.py` measured the embedding model on news pairs; this lane's rules were chosen by reading real collections (see «When you change…»).
- From a Mac the requests go out through the VPN, and Railway's address is a data center's: a source may answer differently there. `/status` and «Настройки» name the failing sources.
- The all-in-one app starts the loop too; `NEWS_LOOP=0` keeps it off there (the API still answers).
- **The whole project.** Before committing, run the `check-project` skill.

## What core relies on

- `app.py` and `news/__main__.py` start `loop.run_forever()` in a thread.
- `common/clients.call("news", ...)` reaches the API in-process unless `NEWS_URL` is set.
- «Возможности» and «Мои» (`core/ui/opps.py`): `GET /opps/board` → `soon`, `items`, `new`, `later`, `updated`, `next`, `window_days`, `expected` (`key`, `name`, `opp_type`, `url`, `when`), and `GET /opps?status=tracked,applied&limit=`; each opportunity with `story_id`, `status`, `opp_type`, `type_short`, `type_name`, `title_ru`, `title`, `meta`, `fit_reason`, `summary_ru`, `apply`, `details`, `over`, `moved`, `starts`, `ends` (and `new` on the board). The sheet and the circle of «Мои» set statuses with `POST /opps/{id}/status` (`tracked`, `applied`, `open`, `hidden`; 422 for another, 404 for no such opportunity). `tabs.page()` fetches the board, «Мои» and «Настройки»'s data before building the page.
- «Настройки» (`core/ui/settings.py`): `GET /settings` (the settings, `opp_type_names`, `weekday_names`, `custom_profile`) and `PUT /settings {key: value}` → the settings, or 422 with `detail` in Russian, one line per refused value (`opps_profile` below 20 or above 3 000 characters, an unknown type…); `GET /status` → `sources` (`total`, `enabled`, `ok`, `pending`, `failing` with `name`, `error`, `fails`), `open`, `tracked`, `unread`, `next_deadline`, `next_tracked`, `shown`, `new`, `later`, `soon`, `updated`, `next_update`, `expected`, `spend` (`today_rub`, `month_rub`, `budget_month_rub`, `daily_budget_rub`), `last_collect` (or null; `at` in the settings' time zone), `loop_alive`, `settings`; `GET /sources` (`id`, `name`, `kind`, `url`, `enabled`, `polled`, `last_ok`, `last_error`, `week`, `silent_days`; never `page_text`), `POST /sources {text}` (422 `detail` on refusal), `DELETE /sources/{id}`, `POST /sources/{id}/enable`.

## What the radar relies on

- **`common`**: `settings` (`REPORTS_DIR`, `NEWS_URL`, `WEB_RETRIEVER`), `auth`, `clients`, `memory`, `text`, `costs`. The radar imports nothing of core.
- **The web search** (`common.settings.WEB_RETRIEVER`, `discover.py`): Tavily's API with `TAVILY_API_KEY` on Railway, the local SearXNG at `SEARX_URL` otherwise; any other retriever leaves the weekly search out, with a warning.
- **DeepSeek**, through gpt-researcher's `create_chat_completion` with `Config(CONFIG_PATH)` (`FAST_LLM`, `LLM_KWARGS`); `common/costs.py` patches it when imported, which is what meters the calls.
- **The sources themselves**: their feeds' addresses and formats, Telegram's preview HTML, Devpost's JSON, awesome-mlss's data file.

## State the radar owns

- `REPORTS_DIR/news.sqlite`, its `backups/` and `.models/`.
- One loop per `REPORTS_DIR`: two loops would poll every source twice. The table's unique keys keep the data right, but the sources see double the requests.
- `items` grows by every post ever seen, backfill included; `slim()` keeps old rows small.

## When you change…

| Change | Also update |
|---|---|
| a field of `/opps`, `/opps/board` (`opps.listing()`, `opps_delivery.dressed()`, `board()`) or `/status` | `core/ui/opps.py`, `core/ui/settings.py` |
| a setting | `LABELS` in `config.py`; «Настройки» when the user should change it there |
| the starting sources | «Sources checked and refused» below, when a source is dropped or refused |
| a table or column | `ADDED_COLUMNS` for databases already on the volume |
| a query on `sources`, `items` or `stories` | its lane: `lane = 'opps'`, so DEEper's switched-off news sources and their posts stay out |
| `link_key()` or `usable_key()` | merging changes; keys already stored keep the old form |
| the embedding model or `embed.text()` | choose `OPPS_THRESHOLD` again on a real collection: similarities of another model are not comparable |
| a merging rule in `dedup.py` (`OPPS_THRESHOLD`, `BOILERPLATE_POSTS`) | merge a real collection anew and read every story of several posts: Devpost's hackathons must stay one story each |
| `opps.EXTRACT_PROMPT`, `describe()` or `deadline()` | rerun `eval/opps/run_extract.py` (about 1 ₽, ask first) and read its misses; `dev/mock_llm.py` recognizes the prompts by «Ты разбираешь анонсы возможностей для студента» and «Ты разбираешь посты-подборки о возможностях» |
| `opps.SIGNAL` | it must keep every opportunity of `eval/opps/cases.jsonl`: run it over the cases before committing |
| an opportunity status | `dedup.OPEN_STORIES` (which stories stay open), `opps.listing()`, `/status` (`open`, `tracked`), `opps_delivery` (`release()`, `board()`, `soon()`, `STATUSES`); the ones the user sets come from the app's sheet and «Мои» (`core/ui/opps.py`) |
| the morning update, the window or «Скоро дедлайн» | rerun the simulated-clock check: a new database releases at once, one found in the evening waits for the morning and is the only new one then, the update is made once, a far one comes in as new when the window reaches it, a big one six months ahead, the weekly day; a tracked deadline appears in `soon` 14 days ahead and leaves it once applied |
| `OPPS_FRESH_DAYS` | `widen_opps_window()` runs once when it grew (`state.opps_fresh_days`); a narrower window revives nothing |
| `annual.EVENTS` | check the month on the event's last editions and that its page answers; its `pattern` must match how announcements name it and not its neighbours (the congress and КМУ ИТМО); «Ждём» in the app and the weekly search follow |
| `discover.QUERIES_PROMPT`, `QUERIES` or the schedule | `dev/mock_llm.py` recognizes the prompt by «поисковых запросов для веб-поиска»; queries a week times four stay well within Tavily's 1 000 a month, which DEEper's researches share |
| the roundup rule (`telegram.is_digest()`, `footer_key()`) | read again which stored posts change (`items.refresh_digests()` with a new `DIGEST_RULE`); real roundups (хакатоны.рус's lists) must stay roundups |
| `SILENT_DAYS` or what `silent_days` means | «Настройки» → «Источники» (its groups) |
| a kind of source | a module in `collectors/` and its entry in `collectors.fetch()` |
| `page.main_text()` or `changed_lines()` | poll each starting page twice: the same page must give no post; check an edit on a saved copy |
| the Telegram selectors | check a channel's page by hand first: `telegram._parse()` on a saved `t.me/s/<channel>`; DEEper reads its news channels with the same code |
