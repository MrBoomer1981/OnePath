# OnePath — исследование на 5–7 минут и что копать дальше

Личный исследовательский поисковик: по теме он сам планирует запросы, ищет и читает десятки источников и пишет отчёт на русском на 5–7 минут чтения — главное, 3–4 раздела, чего пока не знаем, список источников. Главное начинается после отчёта: «что исследовать дальше» запускается одним касанием, продолжение помнит, что уже прочитано в ветке, а у первого отчёта ветки бывает маршрут из нескольких шагов. Для длинных отчётов есть подробный и глубокий режимы. Отчёт сохраняется в PDF, DOCX и Markdown. Работает как веб-приложение по ссылке (его можно поставить на телефон) и из командной строки.

OnePath — исследовательская часть [DEEper](https://github.com/MrBoomer1981/DEEper), отделённая 27.10.2026: тот же поиск, обзор, продолжения, библиотека и «Фокус», без новостей, возможностей и Telegram-бота. Что сделано при разделении и что решить дальше — в `HANDOFF.md`.

Оформление — по брендбуку AVEN (made by aven): тёмная тема «ночь / бумага / бордо / янтарь», шрифты Unbounded, Onest и JetBrains Mono.

Внутри: [GPT Researcher](https://github.com/assafelovic/gpt-researcher) (оркестрация исследования), [SearXNG](https://github.com/searxng/searxng) (бесплатный веб-поиск) или Tavily, научные базы arXiv и OpenAlex, модель DeepSeek.

## Режимы

| Режим | Что делает | Пример |
|---|---|---|
| `quick` — «Обзор», по умолчанию | один проход поиска, отчёт на 5–7 минут чтения: «Главное», 3–4 раздела, «Чего пока не знаем» | ~1,5–3 мин на Pro с проверкой фактов, 800–1 000 слов (5–6 минут), ≈ 2–2,7 ₽ |
| `detailed` — «Подробно» | введение, отдельное исследование под каждую подтему (все сразу), заключение | ~5–7 мин на Pro, ~5 на Flash; до 5 000 слов (обычно 3,5–4,5 тыс., около 20 минут чтения), 35–40 источников в тексте |
| `deep` — «Глубоко» | рекурсивный поиск вширь и вглубь, затем один отчёт | дольше всех |

Источники: `web` (SearXNG или Tavily), `academic` (arXiv, OpenAlex), `all` — по умолчанию.

Обзор — 800–1 000 слов без списка источников (замер на 4 темах: в среднем 2:08 и 2,44 ₽ с проверкой фактов), любой отчёт не длиннее 5 000 слов: подробный делит их между введением, разделами и заключением. Время чтения считается из 180 слов в минуту и видно на отчёте, в «Библиотеке» и на карточках продолжений. Итоговый текст и ответы на вопросы пишет DeepSeek V4 Pro (`--writer pro`, по умолчанию), поиск, планирование и отбор источников — DeepSeek Flash. Для дешёвых черновиков: `--writer flash` или переключатель «Pro / Flash» в приложении. Стоимость каждого отчёта и вопроса считается по реальным токенам и тарифам DeepSeek (с учётом ночной скидки) и показывается в рублях.

Поиск с упором на англоязычные источники: модель формулирует поисковые запросы на английском (для тем про конкретную страну — один на её языке), исходный запрос ищется как есть, а отчёт пишется на русском. На тестовой теме доля англоязычных источников выросла с 26% до 82%.

Отбор источников: до скачивания страниц модель видит заголовок и описание каждого найденного результата и ставит оценку 0–3 за релевантность теме, надёжность и свежесть. Известные домены (`.gov`, `.edu`, научные издательства, IEA, ООН, крупные СМИ) только повышают оценку релевантного источника. Не по теме, магазины, соцсети и мусор отбрасываются, SEO-блоги берутся, только если ничего лучше нет. С одного сайта — не больше 2 ссылок на запрос и 5 на исследование. На тестовой теме: статей не по теме было 18 из 32, стало 0; доменов 11 → 16; доля источников, использованных в тексте, 12% → 36%. Отключить: `SOURCE_FILTER=off`.

## Запуск на своём компьютере

Нужны Docker, [uv](https://docs.astral.sh/uv/) и ключ [DeepSeek](https://platform.deepseek.com/api_keys). На macOS для PDF: `brew install pango`.

```bash
cp .env.example .env          # впишите DEEPSEEK_API_KEY и SEARXNG_SECRET (openssl rand -hex 32)
docker compose up -d          # локальный SearXNG на 127.0.0.1:8080
uv run research.py "тема"     # обзор на 5–7 минут; отчёт появится в reports/
uv run research.py "тема" --mode detailed   # подробный отчёт
uv run app.py                 # приложение и исследователь в одном процессе: http://127.0.0.1:8501
```

## Из чего состоит

Три части, каждую можно улучшать и перезапускать отдельно:

| Часть | Что делает |
|---|---|
| **core** — ядро | веб-приложение, API, библиотека отчётов, очередь исследований, список заблокированных сайтов |
| **worker** — исследователь | само исследование (GPT Researcher и наши доработки), подсказки, ответы на вопросы, сборка PDF и DOCX |
| **search** — поиск | отбор источников и чтение страниц с запасными способами (Europe PMC, OpenAlex, Jina Reader) |

`uv run app.py` запускает всё в одном процессе — так работает и Railway. По отдельности: `uv run python -m my_browser.core` (и `.worker`, `.search`) с адресами друг друга в `CORE_URL`, `WORKER_URL`, `SEARCH_URL` и общим `SERVICE_TOKEN`. Очередь исследований хранится в базе: если сервер перезапустится посреди исследования, оно станет «прервано» и его можно перезапустить кнопкой в приложении.

У папки каждой части (`my_browser/core`, `worker`, `search`, а ещё `common`, `eval` и `proxy`) свой `CLAUDE.md`: что делает часть, как её запустить и проверить отдельно и чего от неё ждут остальные. Перед коммитом — `/check-project`: все модули импортируются, а одно исследование проходит целиком с тестовой моделью `dev/mock_llm.py` вместо DeepSeek.

## Приложение (телефон, Mac, браузер)

Сделано прежде всего для телефона. Внизу четыре раздела: «Поиск», «Радар», «Библиотека», «Фокус». Они переключаются мгновенно, без перезагрузки страницы, а отчёт и ход исследования открываются с плавным переходом. Оформление и маскот Дип-Диггер описаны в `DESIGN_HANDOFF.md`.

- **Поиск.** Тема вводится в поле внизу экрана. Кнопка режима в поле («Обзор») открывает настройки: режим, источники, модель, проверку фактов и «Уточнить тему». Уточнение задаёт 2–3 вопроса с вариантами (регион, цель, аспект), и ответы встраиваются в тему.
- **Ход исследования.** Процент, этап и последние прочитанные источники. Когда отчёт начинает писаться, текст появляется на экране абзацами — его можно читать, не дожидаясь конца. Если к готовности вы уже листаете, отчёт не откроется сам: внизу появится «Отчёт готов — открыть с этого места». Исследование, которое ещё не началось, можно отменить. Экран можно закрыть: отчёт появится в «Библиотеке».
- **Отчёт.** На экране только текст, над ним — время чтения и, если ветка идёт по маршруту, «маршрут · 2 / 5» со списком шагов. Ссылки заменены номерами, оглавление «3 / 9 ▾» следит за прокруткой. В «⋯» лежат PDF, DOCX и MD, источники с блокировкой сайтов и вопросы по отчёту. Там же «Сократить до 1 500 слов»: Pro оставляет выводы, ключевые факты и числа с их ссылками, а краткая версия сохраняется рядом с полной. На отчёте в 7 500 слов это заняло 28 с и стоило 2,15 ₽. Выделенный текст можно сохранить в закладки, задать по нему вопрос или начать по нему новое исследование («Глубже»).
- **«Что исследовать дальше»** в конце отчёта — главное после самого отчёта. Первой идёт следующая остановка маршрута, если он есть, затем четыре темы разных видов: «Глубже», «Против» (самые сильные контраргументы) и две из «На практике», «Для меня» (по интересам из «Фокуса»), «Свежее», «Рядом». На каждой — зачем это читать, время чтения и цена. Касание сразу запускает исследование (5 секунд его можно отменить), и новый отчёт становится продолжением текущего: модель знает «Главное» прочитанных отчётов ветки, не пересказывает их и начинает с нового. Маршрут предлагает первый отчёт ветки, если тема широкая: 3–5 следующих шагов, как короткий курс; каждый шаг знает, где он в маршруте, и не залезает в соседние. Рядом показаны продолжения и похожие отчёты из библиотеки. Тот же раздел есть в конце PDF, DOCX и Markdown. Если ответа на вопрос в отчёте нет, приложение предложит тему для отдельного исследования.
- **«Проверка фактов»**: после написания отчёта каждое утверждение со ссылкой сверяется с той страницей, которую читало исследование. Если сказанное есть в другом прочитанном источнике, ссылка меняется на него; если источник даёт другие числа, даты или имена, предложение исправляется по нему. Неподтверждённые места отмечены «?» в тексте и собраны в разделе «Проверка фактов» в конце отчёта (и в PDF, DOCX, Markdown). По умолчанию проверка включена во всех режимах. Переключатель есть в «Подробно» на экране поиска и в «Фокусе».
- **Библиотека**: отчёты со временем чтения (идущие исследования сверху), закладки и поиск по всем отчётам.
- **Фокус**: настройки по умолчанию и пресеты («Учёный», «Аналитик», «Новости»), сайты, которые не брать, граффити.
- **Радар**: темы «Что исследовать дальше» из отчётов, которые ещё не исследованы: свежая — карточкой, остальные списком; касание запускает исследование, как под отчётом. (В DEEper здесь ещё новости об ИИ и возможности — в OnePath их нет.)

```bash
uv run app.py                 # http://127.0.0.1:8501 (порт 8080 занят локальным SearXNG)
```

На Railway приложение закрыто паролем `APP_PASSWORD`.

**Установить без App Store.** На iPhone: Safari → «Поделиться» → «На экран Домой». На Mac: Safari → «Файл» → «Добавить в Dock». Появится отдельное приложение OnePath со своей иконкой (на Mac — в Dock, Launchpad, Spotlight и Cmd+Tab).

## Деплой на Railway

Сборка по `Dockerfile`, одна реплика; пуш в `main` выкатывается сам. SearXNG на Railway не поднимается, поэтому веб-поиск там идёт через Tavily (бесплатно 1000 запросов в месяц): он включается сам, когда задан `TAVILY_API_KEY`, а `SEARX_URL` — нет. Явно выбрать поиск можно переменной `WEB_RETRIEVER`.

Переменные сервиса:

| Переменная | Значение |
|---|---|
| `DEEPSEEK_API_KEY` | ключ DeepSeek |
| `APP_PASSWORD` | пароль входа в веб-приложение |
| `TAVILY_API_KEY` | ключ [Tavily](https://app.tavily.com) |
| `JINA_API_KEY` | необязательно: бесплатный ключ [Jina Reader](https://jina.ai/reader). Страницы, которые не скачались напрямую, читаются через Jina: с ключом 500 в минуту, без ключа 20 |

Чтобы отчёты и история переживали передеплой, к сервису подключён Volume с путём монтирования `/app/reports`.

**Из России без VPN.** Адрес Railway (`*.up.railway.app`) из российских сетей не открывается, а Cloudflare открывается. Поэтому перед приложением стоит бесплатный прокси на Cloudflare Workers (`proxy/`): телефон открывает `onepath.<поддомен>.workers.dev`, а прокси передаёт всё приложению на Railway. Выложить его: в папке `proxy/` выполнить `npx wrangler login`, `npx wrangler secret put ORIGIN` (адрес приложения на Railway) и `npx wrangler deploy`. На мобильном интернете прокси не открывается: российские провайдеры пропускают к адресам Cloudflare только первые ~16 КБ на соединение.

## Настройки

Модели, длина отчётов, число подтем и параметры глубокого режима — в `config.json`. Любой ключ оттуда можно переопределить переменной окружения или строкой в `.env`.

## Замеры качества

```bash
uv run eval/run.py                    # 7 постоянных тем из eval/topics.txt, ≈ 10 ₽ за прогон
uv run eval/run.py --topics 1,4 --label проба
uv run eval/run.py --factcheck        # с проверкой фактов: точность цитат до и после исправлений
uv run eval/run.py --rejudge 2026-10-18_2327_3.1-reader   # заново оценить отчёты прошлого замера
```

Каждая тема проходит обычное исследование (обзор, текст пишет Flash; `--writer pro` — как в приложении), отчёты складываются в `eval/reports`, а не в библиотеку. Таблица с источниками, долей англоязычных и авторитетных сайтов, нескачанными страницами, стоимостью и точностью цитирования появляется в `eval/results/` рядом со средними прошлого замера. Так видно, улучшило ли поиск очередное изменение.
